# 밖에서 집 PC에 묻기 (로키드 사용자 지정 에이전트)

[English](ROKID_AGENT.md)

로키드 안경은 말한 내용을 내가 만든 "사용자 지정 에이전트"(링주 플랫폼, rizon.rokid.com)로 보낼 수
있습니다. Wavrel 중계 서버가 그 에이전트입니다. 서버는 스스로 답하지 않고 질문을 집의 Wavrel 데스크톱
앱에 넘기며, 앱에서 고른 모델이 답하고 그 답이 렌즈에 뜹니다. 앱이 서버로 나가는 연결을 열어 두므로
PC에는 공인 주소도, 열린 포트도 필요 없습니다.

```
안경 ─ 로키드 클라우드 ─ HTTPS POST /rokid/sse (Bearer AK) ─┐
                                                           ├─ 중계 서버 (agent.wavrel.com)
Wavrel 데스크톱 앱 ── WSS /link (Bearer PC 토큰), 나가는 연결 ─┘
        └─ lab/in/ask → 고른 모델(Ollama) → lab/out/notify → 연결로 되돌려 보냄
```

휴대폰 중계 앱(Wavrel Relay)은 거치지 않습니다. 집에서는 Relay를, 밖에서는 이 길을 씁니다.

## 무엇이 어디로 가나

| 데이터 | 가는 곳 | 보관 |
|---|---|---|
| 마지막으로 말한 내용(300자까지) | 로키드 클라우드 → 서버 → 내 PC | 서버에는 남기지 않음. PC의 모델 화면에 보임 |
| 플랫폼이 함께 보내는 이전 대화, 사진, 위치, 날씨, 배터리 | 서버가 요청을 읽자마자 버림 | 없음 |
| 답(400자까지, 앱은 90자 안으로 씀) | PC → 서버 → 로키드 클라우드 → 안경 | 서버에는 남기지 않음 |
| 서버 기록 | 경로, 상태 코드, 걸린 시간만 | 인스턴스의 systemd 저널 |

## 보안

- **비밀값 두 개**를 SSM 파라미터 스토어(SecureString, 서울)에 따로 둡니다. 로키드 플랫폼용
  `/wavrel/relay/rokid-ak`, 데스크톱 앱용 `/wavrel/relay/home-token`. 배포 워크플로가 처음 한 번 무작위로
  만들고 출력하지 않습니다. 한쪽 값으로 다른 쪽 문을 열 수 없습니다.
- **무차별 대입**: 한 주소에서 10분 안에 틀린 키가 10번 오면 15분 동안 막습니다.
- **답하는 PC는 하나**: 먼저 연결한 앱이 답하고, 같은 토큰을 쓴 다른 PC는 기다렸다가 먼저 PC가 끊기면
  이어받습니다(닫기 코드 4001). 말이 없는 연결은 1분 안에 정리합니다.
- **연결로 할 수 있는 일**: 질문을 내려보내고 그 답을 올려보내는 것뿐입니다. 앱은 질문을 자기 창의
  `lab/in/ask`로 바꾸고, 50초 안에 그 질문에 대해 창이 낸 알림만 돌려보냅니다. 허브에 발행하거나
  설정을 바꾸거나 PC의 다른 곳에 닿을 수 없습니다.
- **앱 안에서**: 주소는 `wss://`만 받습니다(같은 PC의 시험 서버만 `ws://` 허용). 토큰은 허브 비밀번호처럼
  OS 암호화 저장소에 봉인하고, 저장하면 입력칸을 비우며 창에는 다시 돌려주지 않습니다.
- **서버**: t4g.micro 한 대의 Amazon Linux 2023, TLS는 Caddy(Let's Encrypt, 버전 고정과 SHA-512 확인),
  Node.js는 권한을 좁힌 systemd 서비스, 보안 업데이트는 매일 자동 적용. SSH 키와 22번 포트가 없고,
  워크플로가 SSM Run Command로 커밋마다 설치합니다. 인스턴스 역할은 자기 파라미터 두 개만 읽습니다.

## 설정 (wavrel.com 운영자)

1. **서버**: `main`에 병합하면 `server` 워크플로가 `wavrel-relay` 스택([infra/server.yml](../infra/server.yml))과
   비밀값 두 개를 만들고 서버를 설치합니다.
2. **DNS**: Cloudflare에 `agent` → 워크플로가 출력한 `PublicIp`, A 레코드, **DNS only**로 추가합니다.
   인증서는 Caddy가 1분 안에 스스로 받습니다. 워크플로를 다시 돌리면 확인 단계가 통과합니다.
3. **값 두 개 복사**: AWS 콘솔 → Systems Manager → 파라미터 스토어(서울) → 각 파라미터 열기 →
   "복호화된 값 표시".
4. **로키드 플랫폼**: developer.rokid.com에 로그인(실명 인증 필요)한 뒤 rizon.rokid.com에서 타사 에이전트를
   "사용자 지정 에이전트(自定义智能体)" 종류로 만듭니다. URL `https://agent.wavrel.com/rokid/sse`,
   인증 방식 Bearer Token, AK에는 `rokid-ak` 값. **제출(提审)은 누르지 않습니다.** 제출하지 않은
   에이전트는 나만 씁니다.
5. **데스크톱 앱**: 모델 화면 → 밖에서 묻기에 주소 `wss://agent.wavrel.com/link`, PC 토큰에 `home-token`
   값을 넣고 "저장하고 연결". 그 위의 "휴대폰·안경 질문에 답하기"를 켜고 모델을 고릅니다.
6. **시험**: 안경에서 내 에이전트로 바꾼 뒤 물어봅니다. 질문은 모델 화면에, 답은 렌즈에 뜹니다.
   PC가 꺼져 있으면 렌즈가 그렇게 알려 줍니다.

## 직접 띄우기

저장소를 포크하고 [infra/bootstrap.yml](../infra/bootstrap.yml)을 한 번 배포한 뒤, 저장소 변수
`AWS_DEPLOY_ROLE_ARN`을 정하고 [.github/workflows/server.yml](../.github/workflows/server.yml)의 `DOMAIN`을
바꿔 위 순서를 내 도메인으로 따릅니다. 비용은 한 달 약 10달러(t4g.micro, 공인 IPv4 주소, 8GB 디스크)입니다.

## 프로토콜 메모

요청과 이벤트 형식은 로키드의 공개 예시와 커뮤니티 브리지를 따릅니다. `message_id`, `agent_id`,
`message[]`, `metadata`를 담은 JSON POST에 `event:message` / `data:{…}` 이벤트(`answer_stream`)로 답하고,
마지막에 `is_finish: true`인 빈 이벤트를 보냅니다. 서버는 `: keepalive` 주석을 바로 한 번, PC가 생각하는
동안 5초마다 보냅니다. 사진만 있는 질문에는 말로 물어 달라는 짧은 안내로 답하고, 사진은 받아 오지 않습니다.

## 시험과 상태

T-SRV-001~010, T-LNK-001(`tests/server.test.mjs`)은 실제 서버와 데스크톱 연결을 맞붙여 형식, 키,
차단, 시간 초과, 기다리는 두 번째 PC, 다시 보낸 요청, 사진을 확인합니다. 앱 연기 시험은 실제 Electron
앱을 로컬 서버에 연결해, 로키드 형식의 요청에 고른 모델이 답하는지와 토큰이 평문으로 남지 않는지
확인합니다.

실제 로키드 플랫폼과 안경으로는 아직 확인하지 않았습니다: **OPERATOR_REQUIRED**.
