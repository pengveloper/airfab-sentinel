프로젝트로 배우기

하나씩 따라 하면 보드에서 렌즈까지 이어지는 작은 실험입니다. 앱의 프로젝트 화면에서도 같은 순서로 체크하며 진행할 수 있습니다.

01

와이파이로 움직임 보기

쉬움약 45분실기 검증 전

공유기와 보드 사이를 사람이 지나가면 와이파이 신호가 흔들립니다. ESPectre 펌웨어로 그 흔들림을 움직임으로 바꾸고, 실제로 지나간 순간과 맞춰 봅니다.

데모로 먼저 보기

배우는 것

  • 와이파이 채널 정보(CSI)로 움직임을 재는 방식
  • 감지율과 헛경보를 세는 검증 세션

부품

  • ESP32-S3 개발 보드 (DevKitC-1, N16R8)
  • 2.4GHz 와이파이 공유기 (집 공유기)
  • 데이터용 USB 케이블

펌웨어와 도구

  • ESPectre

순서

  1. 허브를 켜고 비밀번호를 정합니다.
  2. ESP32-S3에 ESPectre를 굽고, 허브 창의 주소·포트·사용자·비밀번호를 넣습니다.
  3. 보드를 공유기와 2~4m 떨어진 곳에 둡니다.
  4. 움직임 화면에서 세션을 시작하고, 지나갈 때마다 L 키를 누릅니다. 세 번 이상 지나갑니다.
  5. 기록 화면에서 감지율과 헛경보를 확인합니다.

성공 기준

  • 지나간 횟수의 대부분이 감지로 잡힌다
  • 가만히 있을 때 헛경보가 거의 없다

02

블루투스로 어느 방에 있는지 알기

보통약 90분실기 검증 전

보드 세 대를 방마다 두고 ESPresense를 구우면, 휴대폰이나 태그가 보내는 블루투스 신호의 세기로 어느 방에 가까운지 보여 줍니다.

데모로 먼저 보기

배우는 것

  • 신호 세기(RSSI)와 거리의 관계
  • 세 지점으로 위치를 어림하는 삼변측량

부품

  • ESP32-S3 개발 보드 (DevKitC-1, N16R8)
  • ESP32-C3 Super Mini
  • 블루투스를 켠 휴대폰이나 BLE 태그
  • 데이터용 USB 케이블

펌웨어와 도구

  • ESPresense

순서

  1. 보드 세 대(S3 두 대와 C3)에 ESPresense를 굽고, 방 이름을 office, living, entry처럼 다르게 줍니다.
  2. 위치 화면에서 방 크기를 넣고, 배치 편집으로 보드를 실제 자리로 옮깁니다.
  3. 휴대폰을 들고 방을 옮겨 다니며 점이 따라오는지 봅니다.
  4. 자동화에서 '방에 들어오면' 규칙을 켭니다.

성공 기준

  • 방을 옮기면 10초 안에 방 이름이 바뀐다
  • 같은 자리에 있을 때 방이 오락가락하지 않는다

03

움직임 알림을 안경으로 받기

보통약 40분실기 검증 전

1번 프로젝트의 움직임 감지를 휴대폰과 로키드 안경 렌즈에 알림으로 띄웁니다. 시뮬레이터 값은 '시뮬레이션'이라고 표시되어 실측과 섞이지 않습니다.

데모로 먼저 보기

배우는 것

  • 허브의 알림 토픽(lab/out/notify) 구조
  • 휴대폰이 안경으로 알림을 넘기는 방식

부품

  • ESP32-S3 개발 보드 (DevKitC-1, N16R8)
  • 2.4GHz 와이파이 공유기 (집 공유기)
  • Android 휴대폰 (Android 9 이상)
  • 로키드 안경

펌웨어와 도구

  • ESPectre
  • Wavrel Relay

순서

  1. 휴대폰에 Wavrel Relay를 설치하고, 허브 창의 Host 주소와 비밀번호를 넣습니다.
  2. Relay에서 안경을 연결하고 '시험 알림'으로 렌즈에 뜨는지 봅니다.
  3. 자동화에서 '움직임이 있으면 알림' 규칙을 켭니다.
  4. 안경 화면 미리보기로 렌즈에 어떻게 보일지 확인합니다.

성공 기준

  • 움직임 후 몇 초 안에 렌즈에 알림이 뜬다
  • 시뮬레이터 알림에는 '시뮬레이션'이 붙는다

04

안경으로 방 상태 묻기

보통약 30분실기 검증 전

이 PC의 공개 모델(Ollama)이 안경에서 말로 한 질문에 80자 안으로 답합니다. 모델 화면에서 여러 모델의 답과 속도를 먼저 비교해 고릅니다.

배우는 것

  • 로컬 모델의 속도와 품질 비교
  • 짧은 렌즈용 답을 만드는 지시문

부품

  • Ollama를 설치한 PC (그래픽카드 있으면 빠름)
  • Android 휴대폰 (Android 9 이상)
  • 로키드 안경

펌웨어와 도구

  • Ollama
  • Wavrel Relay

순서

  1. Ollama를 설치하고 작은 모델 하나를 받습니다(예: 4B 안팎).
  2. 모델 화면에서 같은 질문을 두세 모델에 던져 답과 속도를 비교합니다.
  3. '휴대폰·안경 질문에 답하기'를 켜고 답할 모델을 고릅니다.
  4. Relay의 '소리 내어 PC에 묻기'로 물어봅니다.

성공 기준

  • 10초 안에 렌즈에 답이 뜬다
  • 답이 두 줄을 넘지 않는다

05

현관 카메라 보기

보통약 40분실기 검증 전

ESP32-CAM에 Tasmota 카메라 펌웨어를 굽고 카메라 화면에서 영상을 봅니다. 움직임 규칙과 함께 쓰면 누가 왔을 때 화면을 바로 확인할 수 있습니다.

배우는 것

  • ESP32-CAM 굽기와 핀 설정(템플릿)
  • 로컬망 안에서만 영상 보기

부품

  • ESP32-CAM과 USB 어댑터
  • 2.4GHz 와이파이 공유기 (집 공유기)
  • 데이터용 USB 케이블

펌웨어와 도구

  • Tasmota (tasmota32-webcam)

순서

  1. 어댑터에 꽂은 ESP32-CAM에 tasmota32-webcam을 굽습니다.
  2. 영상이 안 나오면 AI-Thinker ESP32-CAM 템플릿을 적용합니다.
  3. 스트림 주소(http://카메라 주소:81/stream)를 카메라 화면에 넣습니다.

성공 기준

  • 카메라 화면에 영상이 나온다
  • 같은 와이파이 밖에서는 열리지 않는다

06

밖에서 집 PC에 묻기

도전약 60분실기 검증 전

로키드 앱의 사용자 지정 에이전트가 Wavrel 중계 서버로 질문을 보내고, 서버가 집 PC의 모델에 넘깁니다. PC에는 열린 포트가 필요 없습니다.

배우는 것

  • 나가는 연결로 집 PC를 밖에서 부르는 구조
  • 비밀값 두 개를 나눠 쓰는 이유

부품

  • Ollama를 설치한 PC (그래픽카드 있으면 빠름)
  • Wavrel 중계 서버 (agent.wavrel.com 또는 직접 띄운 서버)
  • 로키드 안경

펌웨어와 도구

  • docs/ROKID_AGENT.ko.md

순서

  1. 4번 프로젝트처럼 모델이 답하게 켭니다.
  2. 모델 화면의 '밖에서 묻기'에 중계 서버 주소와 PC 토큰을 넣습니다.
  3. 링주 플랫폼에 사용자 지정 에이전트를 만들고 URL과 AK를 넣습니다.
  4. 안경에서 그 에이전트로 바꾸고 물어봅니다.

성공 기준

  • 집 밖에서도 렌즈에 답이 뜬다
  • PC를 끄면 렌즈가 'PC가 연결되어 있지 않다'고 알려 준다

07

LED로 상태 보기

쉬움약 30분실기 검증 전

WLED를 구운 보드에 LED 띠를 달고, 움직임이나 방 이동이 있을 때 색으로 알립니다. 화면을 보지 않아도 방 상태를 알 수 있습니다.

데모로 먼저 보기

배우는 것

  • 자동화 규칙이 장치에 명령을 보내는 흐름
  • WLED의 MQTT 명령

부품

  • ESP32-S3 개발 보드 (DevKitC-1, N16R8)
  • WS2812B LED 띠 (5V)
  • 데이터용 USB 케이블

펌웨어와 도구

  • WLED

순서

  1. 보드에 WLED를 굽고, MQTT에 허브 주소와 비밀번호, 토픽 wled/lab을 넣습니다.
  2. LED 띠의 데이터선을 보드의 GPIO에 연결합니다(5V 전원은 따로).
  3. 자동화에서 '움직임이 있으면 LED' 규칙을 켜고 색을 고릅니다.

성공 기준

  • 움직임이 있으면 LED 색이 바뀐다
  • 8초 뒤 원래 색으로 돌아온다
