# Sentinel Lab 사례 정리 (포트폴리오용)

포트폴리오 사이트나 지원서에 옮겨 쓸 수 있도록 정리한 글입니다. 숫자와 상태는 저장소의
README와 증거표를 기준으로 하며, 실측 결과가 나오면 해당 문단을 바꿉니다.

## 한 줄

오픈소스 ESP32 감지 펌웨어 여러 개를 보드별로 올려 한 화면에서 시험하고, 감지 결과를
정답과 맞춰 검증하는 Windows 데스크톱 앱.

## 문제

Wi‑Fi 신호만으로 움직임을 잡는 ESPectre, 블루투스로 위치를 재는 ESPresense처럼 좋은
오픈소스 펌웨어가 많지만, 각자 따로 설치하고 따로 봐야 합니다. 한 보드에는 2.4GHz 무선이
하나뿐이고 라이선스도 달라서 하나로 합칠 수도 없습니다. 또 "잘 된다"는 인상과 실제 감지
성능은 다른 문제인데, 이를 재는 도구가 없었습니다.

## 접근

- 펌웨어는 합치지 않고 보드마다 원본 그대로 올린 뒤, MQTT 메시지 수준에서 통합했습니다.
- 처음에는 Docker로 브로커를 띄웠지만, 설치 부담을 없애려고 브로커를 앱 안에 넣은 데스크톱 앱으로 바꿨습니다. 같은 화면 코드가 정적 웹 데모로도 그대로 돌아갑니다.
- 감지 검증을 제품의 중심에 뒀습니다. 사람이 실제로 지나간 시간(정답)을 따로 기록하고, 펌웨어의 감지와 맞춰 감지, 놓침, 오탐, 재현율을 냅니다.

## 직접 설계한 부분

- **3D 시각화.** WebGL 셰이더로 Wi‑Fi 링크의 프레넬 영역을 바닥에 그리고, 최근 점수를 링크 위의 막으로 세워 임계값을 넘은 구간이 한눈에 보이게 했습니다.
- **정직한 데이터 표시.** 시뮬레이션, 브로커 수신, 하드웨어 검증을 서로 다른 상태로 구분합니다. 브로커가 보관하던 예전 메시지는 증거로 세지 않고, 꺼진 보드가 화면에 유령처럼 남지 않게 했습니다.
- **보안.** 창은 샌드박스에 넣고 검증된 호출 11개로만 시스템과 통신합니다. 허브는 사설망 주소만 받고, 로그인 실패와 연결 수, 메시지 크기를 제한하며, 비밀번호는 Windows 자격 증명 보호로 암호화합니다. 실행 파일은 Electron fuse로 잠갔습니다.
- **배포.** Windows의 게시자 경고는 서명과 평판의 문제라는 점을 조사해, 개인 개발자가 무료로 쓸 수 있는 경고 없는 경로(Microsoft Store의 MSIX)를 선택하고 CI에서 패키지를 빌드합니다. 다른 서명 방식이 왜 맞지 않는지도 문서로 남겼습니다.
- **추적 가능성.** 요구사항 20개를 시험과 증거에 연결했고, 아직 확인하지 못한 항목은 OPERATOR_REQUIRED로 남겨 둡니다.

## 검증 현황 (2026-11-24)

- 자동 시험 26건(데이터 계층 16, 허브 10)과 실제 앱을 띄우는 연기 시험이 통과합니다.
- Windows 빌드와 Defender 검사는 GitHub Actions에서 실행합니다.
- 실제 보드 측정과 Store 설치는 아직입니다. 결과가 나오면 리포트와 함께 이 문단을 바꿉니다.

## 기술

Electron, Node.js(aedes MQTT 브로커), 바닐라 JavaScript, three.js와 GLSL, MQTT, GitHub Actions,
MSIX 패키징. 연동 펌웨어: ESPectre, ESPresense, Tasmota, WLED.

## 배운 점

- 하드웨어가 얽힌 프로젝트는 "무엇을 확인했고 무엇을 아직 못 했는지"를 구분하는 규칙이 먼저 있어야 결과를 믿을 수 있습니다.
- 사용자가 겪는 설치 경고나 방화벽 창 같은 문제는 코드 품질과 별개로 풀어야 하는 배포 설계의 문제입니다.
